# Docs Instructions for AI Agents

This directory is published as `https://gas.moukaeritai.work/`.

## Scope

Files in this directory define the public-facing static website, including:

- `index.html`
- `index.js`
- `find.html`
- `index.css`
- `sw.js`
- `manifest.webmanifest`
- `icons/`
- generated `projects.json`

## Public Site Rules

1. Treat `docs/` as production web content, not scratch space.
2. Assume all paths are served from the site root `/` at `https://gas.moukaeritai.work/`.
3. Prefer root-relative paths for shared public assets such as `/sw.js`, `/manifest.webmanifest`, and `/icons/...`.
4. Keep `index.html` and `find.html` consistent in shared metadata such as theme color, manifest link, and app icon references.
5. Preserve a working experience on both desktop and mobile browsers.

## PWA Rules

1. The site should meet minimal PWA requirements:
   - a valid web app manifest
   - a registered service worker
   - icons for install surfaces
   - HTTPS-compatible asset paths
2. Do not add cache-first or offline caching behavior unless explicitly requested.
3. `sw.js` should stay minimal and should not cache CDN assets or site content by default.
4. If you change manifest fields, make sure they still match the published origin `https://gas.moukaeritai.work/`.

## Generated Files

1. `projects.json` is generated by `automation/stage-1-inventory/generate-public-project-index.py` from canonical project metadata through `automation.shared.project_registry`; the public site must not read repository-owned metadata paths directly.
2. In the split project layout, canonical repository-owned metadata lives at `projects/<SCRIPT_ID>/repository/metadata.json`, while `projects/<SCRIPT_ID>/README.md` remains the human-facing project landing page and `projects/<SCRIPT_ID>/gas/` contains clasp-materialized GAS source.
3. Stage 1 is the authority for Drive-derived project lifecycle. Only projects whose lifecycle is not explicitly `lifecycle.driveInventory = "absent"` are published in `projects.json`.
4. A project becoming `absent` means it disappeared from the latest Drive inventory; it is removed from the public projection but its canonical `projects/<SCRIPT_ID>/` directory and source history are retained. Reappearance can make it publishable again.
5. Public catalog timestamps use Drive authority only:
   - `createdAt` projects `driveApi.createdTime`
   - `updatedAt` projects `driveApi.modifiedTime`
   Apps Script API timestamps, repository commit times, workflow runs, deployment reconciliation, and synchronization attempts must not be substituted for these catalog fields.
6. `hasReadme` is generated from the actual presence of `projects/<SCRIPT_ID>/README.md`.
7. Do not treat disappearance from `projects.json` as evidence that the underlying project directory should be deleted.
8. Do not hand-maintain `projects.json`. Regenerate it with the canonical generator, and require the checked-in projection to match generator output in PR validation.
9. If the project list changes, prefer regenerating it through `.github/workflows/stage-1-inventory.yml` or the canonical Stage 1 scripts.
10. The manual `.github/workflows/diagnose-apps-script-change-signals.yml` workflow is read-only diagnostic evidence only; it must not write `docs/`, regenerate `projects.json`, or become a publication authority.

The public project list is a projection of current Drive lifecycle state. It is not the source of truth for successful source synchronization. That separate checkpoint is stored in each project's `syncState.lastMaterializedAppsScriptUpdateTime`.

## UI Content Rules

1. Keep the top navigation available on public pages.
2. Include links to:
   - `https://moukaeritai.work`
   - `https://gas.moukaeritai.work`
   - `https://github.com/codespaces`
3. Style those links as obvious buttons.
4. Keep footer attribution to Takashi Sasaki and include the `x.com/TakashiSasaki` link.
5. Keep the site clearly oriented around discovering and browsing Google Apps Script projects and related repository information.
6. Preserve project deep links in the form `/?project=<SCRIPT_ID>` when changing navigation or selection behavior.

## Asset Rules

1. Do not assume `docs/moukaeritai-pictgram/` exists. It has been removed.
2. Use assets that actually exist under `docs/`, especially `icons/` for PWA-related icon references.
3. If you add new public assets, make sure they are referenced with paths that work from the deployed origin.

## Implementation Notes

1. `index.html` and `index.js` form the canonical Project Explorer. The app loads `projects.json`, supports client-side project-name search/sort/filter, and keeps the selected project in the `project` query parameter.
2. `find.html` is a legacy compatibility entry point that redirects to the canonical Explorer while preserving a `project` query parameter.
3. The Explorer treats the split project root as a boundary:
   - README rendering fetches `projects/<SCRIPT_ID>/README.md` from the public raw repository branch.
   - the source action links to `projects/<SCRIPT_ID>/gas/`.
   - browser code must not fetch `projects/<SCRIPT_ID>/repository/` or infer publication fields from repository-owned files.
4. Rendered README HTML must be sanitized before insertion into the DOM. If the Markdown renderer or sanitizer is unavailable, fall back to plain text rather than rendering unsanitized HTML.
5. CDN dependencies are currently used for Bootstrap, Marked, and DOMPurify. If changing them, preserve compatibility with the static hosting model.
