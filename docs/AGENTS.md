# Docs Instructions for AI Agents

This directory is published as `https://gas.moukaeritai.work/`.

## Scope

Files in this directory define the public-facing static website, including:

- `index.html`
- `index.js`
- `find.html`
- `index.css`
- `sw.js`
- `manifest.webmanifest`
- `icons/`
- generated `projects.json`

## Public Site Rules

1. Treat `docs/` as production web content, not scratch space.
2. Assume all paths are served from the site root `/` at `https://gas.moukaeritai.work/`.
3. Prefer root-relative paths for shared public assets such as `/sw.js`, `/manifest.webmanifest`, and `/icons/...`.
4. Keep `index.html` and `find.html` consistent in shared metadata such as theme color, manifest link, and app icon references.
5. Preserve a working experience on both desktop and mobile browsers.

## PWA Rules

1. The site should meet minimal PWA requirements:
   - a valid web app manifest
   - a registered service worker
   - icons for install surfaces
   - HTTPS-compatible asset paths
2. Do not add cache-first or offline caching behavior unless explicitly requested.
3. `sw.js` should stay minimal and should not cache CDN assets or site content by default.
4. If you change manifest fields, make sure they still match the published origin `https://gas.moukaeritai.work/`.

## Generated Files

1. `projects.json` is generated by `automation/stage-1-inventory/generate-public-project-index.py` from canonical project metadata.
2. Stage 1 is the authority for Drive-derived project lifecycle. Only projects whose lifecycle is not explicitly `lifecycle.driveInventory = "absent"` are published in `projects.json`.
3. A project becoming `absent` means it disappeared from the latest Drive inventory; it is removed from the public projection but its canonical `projects/<SCRIPT_ID>/` directory and source history are retained. Reappearance can make it publishable again.
4. Do not treat disappearance from `projects.json` as evidence that the underlying project directory should be deleted.
5. Do not hand-maintain `projects.json` unless the user explicitly asks for a one-off edit.
6. If the project list changes, prefer regenerating it through `.github/workflows/stage-1-inventory.yml` or the canonical Stage 1 scripts.
7. The manual `.github/workflows/diagnose-apps-script-change-signals.yml` workflow is read-only diagnostic evidence only; it must not write `docs/`, regenerate `projects.json`, or become a publication authority.

The public project list is a projection of current Drive lifecycle state. It is not the source of truth for successful source synchronization. That separate checkpoint is stored in each project's `syncState.lastMaterializedAppsScriptUpdateTime`.

## UI Content Rules

1. Keep the top-right navigation available on public pages.
2. Include links to:
   - `https://moukaeritai.work`
   - `https://gas.moukaeritai.work`
   - `https://github.com/codespaces`
3. Style those links as obvious buttons.
4. Keep footer attribution to Takashi Sasaki and include the `x.com/TakashiSasaki` link.
5. If you change copy, keep the site clearly oriented around browsing Google Apps Script projects and related repository information.

## Asset Rules

1. Do not assume `docs/moukaeritai-pictgram/` exists. It has been removed.
2. Use assets that actually exist under `docs/`, especially `icons/` for PWA-related icon references.
3. If you add new public assets, make sure they are referenced with paths that work from the deployed origin.

## Implementation Notes

1. `find.html` loads `projects.json` and fetches project README files from `../projects/<SCRIPT_ID>/README.md`.
2. `index.html` embeds `find.html` in an iframe, so changes that affect layout height or cross-document behavior should be tested carefully.
3. CDN dependencies are currently used for Bootstrap and Marked. If changing them, preserve compatibility with the static hosting model.
